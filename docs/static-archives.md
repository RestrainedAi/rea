# Optional static Inno 7 and 7z reader

REA's existing `inspect_artifact` and `extract_artifact` tools can inventory and export supported Inno 7 installers and 7z archives through an explicitly configured analyzer. CLI commands are `inspect-artifact` and `extract-artifact`; `open_binary` admits 7z from its bytes. Ordinary PE identity stays PE. The existing independent Instyler reader remains the first PE profile.

The optional analyzer executes trusted parser code. Supplied applications, installer scripts, drivers and archive payloads remain inert. It uses a private immutable input snapshot, opaque ordinal output names, a Windows Job with a 1 GiB process-tree commit limit, a 120 second deadline and bounded complete diagnostics. The current optional implementation requires Windows native private-runtime and process-ownership support.

## Configuration

Set `REA_STATIC_ARCHIVE_MANIFEST` to an absolute installation manifest. Keep the analyzer, pinned Python runtime, dependencies and manifest in the application folder. The reader never downloads or installs dependencies automatically. REA's maintained deployment uses the separately maintained [REA Binary Refinery fork](https://github.com/RestrainedAi/rea-binary-refinery), based on Binary Refinery 0.11.2, and portable CPython 3.14.10.

The installation manifest uses protocol `rea.static-archive-installation/1`, an absolute `root`, fixed relative `python` and `bridge` paths, pinned interpreter/backend versions, our backend repository/revision, and every required file's relative path, byte count and SHA-256. REA verifies the files and retains their admitted handles through decoding. The manifest is trusted operator configuration; archive data cannot select a command, wrapper, password or destination.

Admitted files use native immutable Windows leases. The input byte ceiling is checked on that lease before copying, so replacement or growth cannot bypass the copy budget. Parser/interpreter pins have an aggregate 256 MiB ceiling. Python uses a fresh private bytecode-cache prefix with cache writes disabled; existing source-checkout bytecode caches are not used.

## Supported profiles and limits

The strict analyzer admits the qualified Inno 7.0.0.3 Unicode profile and 7z version 0.4 with copy, LZMA, LZMA2 and the qualified x86 BCJ chain. Other versions, codecs, encrypted data, incomplete parsing, warning-bearing parses and ambiguous framing fail explicitly. There is no password guessing, installer emulation or version fallback.

- Source file: at most 128 MiB.
- Declared entries: at most 4,096.
- Aggregate decoded chunks, including decoded headers: at most 256 MiB.
- Decoded header and protocol metadata: at most 8 MiB each.
- LZMA dictionary: at most 64 MiB, checked before decoder creation.

Limits are checked before count-driven allocation or decompression. A bounded decoder can allocate one sentinel byte to detect an output overrun. Process memory enforcement complements these format limits. A source over the profile ceiling is refused, even if a larger archive could fit available disk space.

Every materialized file has an independently observed SHA-256 and size. Declared checksums are checked by the strict profile and preserved in generated `__rea_archive_metadata.json`, along with literal names, ordinals, profile and compression metadata. Paths are normalized only for the artifact graph/output; raw names remain in metadata. Unsafe paths, symlinks, special files, duplicates, prefix conflicts, alternate data streams and destination name collisions are refused before public output creation.

The qualified Inno profile declares Windows destination-name semantics. Its backslashes become logical `/` separators, while the exact literal name and UTF-16 bytes remain preserved. 7z uses its own admitted name dialect. Separator projection never expands installer placeholders, resolves traversal or collapses ambiguous repeated separators, and collisions after projection are refused.

Decoded file occurrences have `source_location: null` and no per-file compressed size. Solid compression extents belong to streams; decoded member offsets are separate facts. The metadata file is generated by REA, not claimed to be a member from the source archive. Installer placeholders such as `{app}` remain literal and are never expanded.

Inspection uses private decoded payloads to hash and classify child bytes, then removes its owned cache. Extraction revalidates the selected source identity and each output against the inventory before publishing. Failed preparation, cancellation, failed process cleanup and failed cache/descriptor release retain exact owners for a later close attempt. The decoder's strict integrity refusal is distinct from the artifact workflow's optional record-and-continue policy.

Binary Refinery and its parser guards retain their source notices. The portable Python and pure-magic dependency retain their own licenses. Proprietary installers and bundled executables are analysis inputs and are not included in REA source or distributions.
